Get a concise summary of a file's contents WITHOUT reading the full source code. Use this proactively when exploring a codebase.

WHEN TO USE THIS INSTEAD OF `read`:
- Initial exploration: you've found a candidate file (via glob/grep) but aren't sure if it's relevant
- Understanding a directory: you need to know what each file does to find the right one
- Imports/dependencies: a file imports from another file and you want to know what's there
- Large files (>500 lines): you only need to know roughly what the file does
- You don't yet know if you need to edit this file

DO use `read` (full content) when:
- You're about to edit or modify the file (need exact line numbers)
- You need to verify specific syntax, regex, or implementation details
- The file has fewer than ~50 lines (full read is cheap anyway)
- You need to quote exact code in your response

WORKFLOW PATTERN (recommended):
1. Use `glob`/`grep` to locate candidate files
2. Use `read_summary` on each candidate to understand purpose
3. Use `read` on the 1-2 files you actually need to edit

OUTPUT:
- Returns 2-4 sentences describing the file's purpose, key exports, and main components
- Cached after first generation; same file returns instantly on subsequent calls
- Cache invalidates when the file content changes

The summary is generated by a small model on first request and cached for subsequent calls.
